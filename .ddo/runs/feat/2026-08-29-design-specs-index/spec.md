# 样式规则拆分与规范索引 Spec

> 本文档用于确认 agent 是否正确理解用户关于「以 DESIGN.md 为基础，构建结构化的 AI Coding 规范索引目录，将样式规则拆分为各类组件的样式规则」的需求。

## 对齐摘要

- 用户目标：把项目根的 DESIGN.md（设计/样式规则唯一权威）拆分重组为一个结构化的「AI Coding 规范索引目录」，按组件组织样式规则。
- 期望交付：带索引入口的规范目录（内含按组件拆分的样式规则文件）+ 规范目录内的 DESIGN.md 整体索引文件 + 仓库根新增的 AGENTS.md，构成分层加载的 AI 上下文。
- 新增交付：给 AI 补充一条流程规则——执行 `git push` 前必须提示用户是否沉淀本次需求的组件样式变更；用户确认后通过 git 查看变更并整理沉淀到样式架构规则。
- 关键边界：本次只重组/拆分规则文档并写入流程规则，不改变任何视觉规则取值，不改动 `src/` 运行时样式代码与 `tokens.css` 取值。
- 当前状态：BQ-1 已解决；revision 2 已按 plan 门反馈写回，等待用户批准。

## 用户目标

- 构建一个结构化的 AI Coding 规范索引目录。
- 以 DESIGN.md 为基础，将这份样式规则文件拆分为各类组件的样式规则。
- 便于后续持续发展，保证后面实现的一致性。
- 新增根级 AGENTS.md 供 AI 理解本仓库逻辑；在规范目录中维护 DESIGN.md 作为整体索引文件；通过分层加载为 AI 构建更好的上下文环境。
- 给 AI 补充规则：后续执行 `git push` 前需提示用户是否沉淀本次需求的组件样式变更；用户确认需要整理沉淀后，通过 git 查看本次变更，再整理沉淀到样式架构规则中。

---

## 范围与非目标

### In Scope

- 建立规范索引目录与索引入口（可从组件名定位到对应样式规则文件）。
- 将 DESIGN.md §4 的各组件样式规则拆分为独立的组件样式规则文件。
- 将 DESIGN.md 中组件之外的规则（色彩、排版、间距/圆角、阴影层级、图标、滚动条、响应式、Do/Don't、token 速查等）安置到同一索引下的基础/全局规则文件，保证原文规则全覆盖、不丢失。
- 原根目录 DESIGN.md 迁入规范目录，重构为整体索引文件（分层加载的中间层）。
- 新增仓库根级 AGENTS.md，帮助 AI 理解本仓库逻辑（分层加载的入口层）。
- 写入「git push 前提示沉淀样式变更」的 AI 流程规则（含触发时机、询问动作、确认后的沉淀流程）。
- 同步更新 CLAUDE.md 中「两条权威来源」的指向，使其与新的规范结构一致。

### Non-goals

- 不改任何视觉规则的取值（色值、字号、间距、圆角、阴影等一律保持 DESIGN.md / tokens.css 现状）。
- 不修改 `src/styles/tokens.css` 的取值与 `src/` 下任何组件实现代码。
- 不在本次为尚不存在的组件（如 Modal、Dropdown）预写规则文件。
- 不把规范索引发布为站点页面或改动产品介绍页内容。
- 不实现自动化的 push 拦截钩子（该规则以文档形式约束 AI 行为，不落地为 git hooks）。

## 约束与保留术语

- 保留用户术语：「AI Coding 规范索引目录」「样式规则」「各类组件的样式规则」「拆分」「分层加载」「整体索引文件」「AGENTS.md」「沉淀」；文档中沿用原词，不做静默改名。
- 用户明确约束：规范结构采用分层加载（入口层 AGENTS.md → 索引层规范目录 DESIGN.md → 规则层各组件/基础规则文件），为 AI 构建上下文。
- 用户明确约束：样式变更的沉淀必须发生在 `git push` 之前，且以用户确认为前提（提示 → 用户同意 → git 查看变更 → 整理沉淀）。
- 项目事实约束：CLAUDE.md 铁律（禁裸 hex、代码块恒暗、函数组件 + 命名导出、CSS Modules、图标仅用 `Icon.tsx` 内联 SVG）；`tokens.css` 是样式的唯一数据来源。
- 项目事实约束：本仓库命令须走 `nvm exec 22`；完成标准为 `npm run lint` 与 `npm run build` 通过（本次改动以文档为主，但不得破坏该标准）。
- 项目事实约束：根目录 DESIGN.md 当前是未入 git 的文件，本次将随特性分支以新结构纳入版本管理。
